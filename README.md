# ARBITER Gate 示範 repo

這個 repo 是 **ARBITER Gate** 的示範：每次有人開 Pull Request 改到合約，GitHub 會自動請 ARBITER Gate 檢查這次改到的函式，
**只有在攻擊真的在模擬區塊鏈上成功時才擋合併**。

## 裡面有什麼

| 檔案 | 內容 |
|---|---|
| `src/StakingVault.sol` | 一個簡單的質押金庫：`stake()` 存 ETH、`unstake()` 領回。main 上是**修好的版本**（先把帳記好，再把錢轉出去）。 |
| `test/StakingVault.t.sol` | 誠實使用者的測試：存多少、領回多少，金庫不會少掉別人的錢。 |
| `.github/workflows/arbiter-gate.yml` | PR 時觸發的檢查（job 名稱「ARBITER Gate」，是 main 合併前必須通過的檢查）。 |
| `.github/actions/arbiter-gate/action.yml` | 檢查實際做的事（見下方）。 |

這裡的合約與測試都是 ARBITER Gate 團隊自己寫的示範程式，不是任何真實專案的程式碼。

## 開 PR 之後會發生什麼

1. 比對這個 PR 改到哪些函式（只看有改到函式的 `.sol` 檔；介面、mock、測試檔會略過）。
2. AI 讀這些合約，試著寫出攻擊，並在**模擬區塊鏈**上實際執行。成功的條件由系統持有，AI 不能自己宣稱成功。
3. 結果貼在 PR 留言，分成四種：

| 判定 | 意思 | 會不會擋合併 |
|---|---|---|
| 已證實可攻擊 | 攻擊在模擬區塊鏈上成功，受害者真的少拿回錢 | **擋**（檢查失敗，結束碼 1） |
| 無法判定（稽核未完成） | 稽核沒有跑完（例如合約編譯不過），沒有結論 | **不放行**（結束碼 2），但這不是發現漏洞 |
| 靜態工具提示但未證實 | 自動掃描工具覺得可疑，但 AI 沒有寫出成功的攻擊 | 不擋（Security 分頁會有 warning） |
| 未發現可證明攻擊（不等於安全） | 這次沒有找到能成功的攻擊 | 不擋。**這不代表合約沒有漏洞** |

4. 證實可攻擊時，留言會附上損失重現（A／B／G：沒攻擊時受害者取回多少、有攻擊時取回多少、攻擊者賺多少），
   以及已通過驗證的修補建議（同一個攻擊重打要失效、誠實使用者取回的錢不能變少）；能對到 PR 改到的行時，會用 GitHub 的 suggestion 讓你一鍵套用。
5. 「未涵蓋」：這一版只稽核有函式被改到的檔案。只刪程式碼、只改函式外的常數或狀態變數，會在留言的「未涵蓋」照實列出，不算「未發現」。

## 防護設計（給維護者）

- 檢查跑在維護者自己的機器上（self-hosted runner，只註冊在這個 repo），攻擊與編譯都在**每次一個、不連網的容器**裡執行。
- 用 `pull_request` 觸發，不用 `pull_request_target`。從 fork 來的 PR 不會在 runner 上執行它的程式碼，結果一律是「無法判定」；
  外部貢獻者的 PR 也要維護者核准後才會開始跑。
- 模型端點與金鑰只放在 runner 主機上，不放在 GitHub。
